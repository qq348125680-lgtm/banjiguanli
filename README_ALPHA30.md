# V7.0 Alpha 30 · 登录初始化竞态修复

## 修复
- 修复 `auth.getUser()` 初始化响应晚于登录、退出、令牌变更事件时，可能覆盖较新会话状态的问题。
- `src/lib/auth-bootstrap.mjs` 为每次 React 挂载创建独立的门闩：只要收到后续身份事件，初始化响应就不能再写回状态；组件卸载后也不能更新。
- 不改变原数据库、RLS、存量班级记录或业务写入开关；仍然默认只读。
- 保留现有六组导航、学生中心、连续登记和审核中心。

## 本轮验证（当前容器）
- `node --test tests/*.test.mjs`：115/115 通过（包含新增5项初始化竞态回归检查）。
- `npm run verify:source`：既有源码约束检查通过（11+5+3项）。
- `npm run preflight:offline`：33个本地相对导入存在。
- `npm run build`：**未通过**，当前环境缺少 `vite/client` 类型定义，且 npm registry DNS 失败；没有伪造依赖、没有生成 dist。
- 没有执行真实浏览器端到端测试；没有在 Supabase 上运行写入或权限冒充验证。

## 正式环境部署前
1. 在正常可连接 npm 的开发机安装原版锁定版本依赖，生成并提交 `package-lock.json`，再运行 `npm ci`、`npm run build`、`npm test`。
2. 用测试班主任与班干部账号分别检查身份切换、前后台恢复及已停用账号的访问边界。
3. 在隔离测试项目完成数据库审批事务验证后，再考虑开放写入；切勿直接覆盖旧版线上服务。
