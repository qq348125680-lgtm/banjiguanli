## 已开发并通过自动测试的安全只读功能

| 模块 | 当前能力 | 边界 |
| --- | --- | --- |
| 学生中心 | 学号/姓名搜索、5/10/20 人分页、个人五类档案分页 | 学生敏感身份字段不从此列表读取 |
| 座位宿舍 | 当前班级座位号、宿舍和床位对应的已授权只读展示 | 不擅自重新安排座位、寝室 |
| 班干部组织 | 当前班级已授权干部职责、启停及权限摘要 | 不自动修改授权 |
| 考勤助手 | 姓名/学号过滤、未提交筛选、定位下一位、会话内去重统计 | 正式业务写入开关关闭 |
| 审核记录 | 状态分页、待审核区分、操作安全防重 | 审核服务端事务尚未完成隔离验收 |
| 班务记录 | 班主任只读查询考勤、请假、违纪、积分、值日和家校沟通；日期与学生筛选、5/10/20 条分页 | 家校沟通禁止在本入口 CSV 导出 |
| 导出 | 当前已授权页的非家校记录 CSV（防表格公式注入） | 不批量导出学生身份证/手机等信息 |
| 数据分析 | 已授权范围可见人数、当前已加载审核分布与待审计数 | 不将单页统计虚称全班总数 |
| 操作审计 | 中文业务摘要、真实操作人 UID、分页 | 无法确认的操作者不虚构姓名 |
| 积分规则查看 | 使用现有 point_rules 表读取本班规则、启停状态、阈值和来源备注，支持临时分值试算 | 无分值规则不能默认为 0，不计算尚未核定的阈值折算，也不写入学生积分 |
| 当前页记录核对 | 缺勤无备注、待处理请假、缺少值日区域与违纪类别的提示；页面内可标记已查看 | 并非正式异常处置或学校审批；页码、班级或类别切换后重置 |
| 异常核对清单 | 导出本页最多 20 条待人工核对事项的 CSV，带公式注入防护 | 不导出家校沟通；不代表已结案，不包含身份证或电话 |
| 班干部提交核对 | 审核页按真实 UID 分组，展示本页提交量、待审和通过数 | 不推断姓名或全班总工作量，正式权限不变 |
| 班干部身份核对 | 班主任在审核页通过本班学生与干部账号关联，显示可验证的姓名、职责及 UID | 未关联或已归档学生仍保留 UID，不猜姓名；权限失效立即清除 |
| 审核提醒 | 当前页积压天数、重复待审记录、缺考勤状态提醒 | 缺少状态的申请不能直接批准，正式服务端审核仍待验收 |
| 值日助手 | 根据当前页历史建议临时替补、排除不可用人员、拖地与扫地加权、一次性生成 4+3+1+1 九人预排 | 当前页值日历史按唯一记录去重；不核验完整请假或自动执行 |
| 考勤周核对 | 按周一至周日统计当前页可见考勤、迟到两次折算一次的核对参考 | 不代表全周完整数据，不自动改变正式考勤 |
| 考勤提交异常恢复 | 提交前检查本人同班同日已有申请；网络错误或超过30秒未响应时锁定重复提交，读回核对；已驳回可修正后再提交 | 查不到不证明写入未发生，不能盲目重试；跨干部并发最终靠暂未正式安装的唯一索引 |
| 审核异常恢复 | 批准或驳回响应不确定时锁定当前申请，仅通过查询服务端真实审核状态确认 | 只有确认已通过或已驳回才自动解除该项锁定；正式事务仍需隔离实测 |

积分规则暂依赖现有数据库 RLS（仅班主任），尚未经过两账号浏览器验证。此前上传的学生手册是扫描页，文本无法可靠提取，因此未擅自把任何推测的条款写成正式分值。

Alpha 43–44 安全强化：班级权限复核失败或授权被撤销时直接卸载所有业务子模块，防止内部缓存残留；学生名单读取失败即阻断班级页面，其他敏感模块失败则清除对应结果；授权和读请求增加有限超时与可重试提示。

所有上述模块需要在**有权限的隔离测试环境真实登录后**进一步进行手机、电脑浏览器验收；GitHub Pages 安全公开预览不能展示这些真实数据界面。

## Alpha 45 隔离验收准备（尚未在正式库执行）

1. `sql/alpha45_PREFLIGHT_READONLY.sql`：只读核对生产/测试项目的 RLS 与唯一约束，不提取学生资料。
2. `sql/alpha45_STAGING_ONLY_SAFE_MIGRATION.sql`：只在隔离 Supabase 数据库安装安全花名册 RPC、同班级校验触发器及原子考勤审核 RPC，保留原有 INSERT 策略。
3. `sql/alpha45_STAGING_ONLY_ROLLBACK.sql`：仅用于独立测试库撤销新增对象，不能替代恢复数据库备份。
4. `STAGING_ACCEPTANCE_ALPHA45.md`：两账号、多班级、停用授权、并发审核和数据恢复验收矩阵。
5. 原有 `sql/alpha9_PROPOSED_NOT_APPLIED.sql` 已停用为不可执行说明，避免误覆盖原政策。
6. 班干部考勤提交已增加调用当前授权花名册验证学生归属，但**没有任何正式写入开关被开启**。

Alpha 47 将隔离迁移的 `v7_pending_student_day_unique` 索引限定为**同班同学生同日期的待审核考勤**，允许同日多条合法请假/违纪申请。真实生产库只读预检的待审核考勤重复组为 0；**该索引尚未安装在正式库**。浏览器的未确认操作标记仅保存账号、班级、日期及 UUID 于当前标签页会话存储，不保存姓名、电话、密码或谈话内容。

## Alpha 47 临时 PostgreSQL 17 真正执行的自动化验收

独立 CI 工作流：[`alpha47-postgres-contract.yml`](.github/workflows/alpha47-postgres-contract.yml)。

- 每次测试创建一次性 PostgreSQL 17 容器，使用虚构两班、两位班主任、两名启用干部、停用干部、匿名角色及学生。
- 真实执行 `sql/alpha45_STAGING_ONLY_SAFE_MIGRATION.sql`，验证花名册权限、跨班级/归档学生写入拒绝、待审核考勤唯一索引、同日两条请假不被误拦截。
- 并发运行两个独立 PostgreSQL 会话审批同一申请，验证只有一个提交成功；批准、驳回、空缺考勤状态及非法类别均有实际数据库断言。
- 执行 `sql/alpha45_STAGING_ONLY_ROLLBACK.sql`，确认新增 RPC、索引、触发器消失且考勤和请假测试记录仍在。
- 运行 `tests/postgres/backup-restore.sh`，备份仅含虚构数据的数据库，主动删除一条测试考勤，再恢复到新的隔离库并核对数量、关联和 RLS 完整性。
- 禁用干部不能读历史申请也不能提交；匿名角色不能调用 V7 花名册 RPC；测试 RLS 条件与当前生产库的核心策略对齐。
- **不连接任何 Supabase 项目、无真实学生信息、无生产密钥。** 这只能证明在隔离 PostgreSQL 中 SQL 能工作，不是 Supabase Auth、真实登录、数据迁移或完整备份恢复的上线通过证明。

## 严格上线门禁

1. 只在独立 Supabase 测试项目验证实际老师与班干部两种账号；先验证 RLS，再开放浏览器数据连接。
2. 现有生产数据库没有 `v7_cadre_roster` 与 `v7_review_attendance` 两个关键函数。班干部花名册读取与考勤事务目前不能按 V7 的预期闭环。
3. Supabase 安全顾问此前报告多个可执行 SECURITY DEFINER 函数警告。逐项审核，不能直接全量撤销权限干扰正式系统。
4. `VITE_ENABLE_WORKFLOW_WRITES=false` 保持关闭。未经验收，禁止发布任何真实写入/审批功能。
5. 跨账号、跨班级、停用/撤销授权、网络异常、切后台恢复、手机触控和电脑桌面均须测试，保留原系统回退方案。
