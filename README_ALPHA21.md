# V7.0 Alpha 21：权限复核刷新

## 基于 Alpha 20 的实质修复

- 点击顶部刷新按钮时，先通过当前登录用户重新读取其班主任和班干部授权班级，再执行数据刷新。
- 若当前班级已不在授权范围，立即清除旧学生名单、审核列表、审计日志、待审核数量、档案状态、选中学生及操作反馈，自动选择仍有权限的班级（如果没有则置空）。
- 权限复核进行中禁用提交/审批；权限复核失败或被撤销后继续禁止写入，避免把缓存当作有效授权。
- 保留 Alpha 20 的同班网络暂时失败时的快照机制，不能拿快照代替真实权限。
- 添加单元测试覆盖有效授权、权限撤销、所有授权撤销、异常输入、校验调用顺序。

## 结果与限制

- `npm test`：67项测试通过；`npm run verify:source`：19项源码断言通过；本地导入路径31处存在。
- 11个 TS/TSX 文件通过 TypeScript 的 transpileModule 语法转换；**这不是完整类型检查**。
- React/Vite/@supabase/supabase-js 等依赖未安装，正式 `npm run build` 和浏览器回归尚未通过。
- 线上数据库、GitHub 和真实班级数据均未修改；审核数据库函数仍需要在隔离环境验收，正式写入仍由 `.env` 开关控制（默认关闭）。
- 不能仅靠前端授权复核实现安全隔离，数据库 RLS/RPC 必须独立校验。若账户处于已登录状态但仍无法查询授权，严禁使用 service_role 绕过。

## 本地启动

使用有 npm 网络访问能力的电脑：`npm ci`（前提是已创建并校验 lockfile）或 `npm install`，然后 `npm run build` / `npm run dev`。复制 `.env.example` 为 `.env.local`，只填公开 publishable/anon key；不要在浏览器放置 service_role 密钥。首次完整安装成功后应提交锁文件。
